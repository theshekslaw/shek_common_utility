# 01 — Align `BrainClient` with the schema-registry API (v0.2)

## Context (why now)

`BrainClient` in v0.1.0 has stub methods (`ingest_paper`, `semantic_search`, etc.) modeled on the earlier "paper-centric brain" plan. That model is now obsolete — `shek_brain` is being redesigned as a **generic ingest + retrieval hub** with a schema-registry API and a memory-graph layer over SurrealDB. The client must catch up before `shek_brain` v0.1.0 ships.

## Non-goals

- Not adding OpenTelemetry (deferred).
- Not moving to a private PyPI.
- Not adding synchronous variants — async only.

## Design

Replace the paper-specific methods with the generic surface planned for `shek_brain`:

```python
class BrainClient:
    async def register_schema(self, kind: str, json_schema: dict) -> RegisterSchemaResult: ...
    async def list_kinds(self) -> list[KindInfo]: ...
    async def ingest(self, item: IngestRequest) -> IngestResult: ...
    async def get(self, item_id: str) -> Item: ...
    async def search(
        self,
        query: str,
        *,
        kind: str | None = None,
        strategy: SearchStrategy = SearchStrategy.AUTO,
        k: int = 10,
    ) -> SearchResult: ...
    async def graph_neighborhood(self, focus_id: str, depth: int = 2) -> GraphView: ...
    async def health(self) -> HealthReport: ...
```

Add pydantic response models under `shek_common_utility/brain_types.py` — mirroring what `shek_brain` returns. Consumers import both the client and the types.

Files to modify:
- `src/shek_common_utility/brain_client.py` — rewrite methods.
- `src/shek_common_utility/brain_types.py` — **new**.
- `src/shek_common_utility/__init__.py` — export new symbols.
- `tests/test_smoke.py` — update assertions.

- Once `shek_brain` v0.1.0 ships, do a live integration test: `pytest tests/integration/test_brain_live.py` (requires local `shek_brain` container).

## Blocked on

- `shek_brain` v0.1.0 API design must be finalized first. This plan waits on `shek_brain/.claude/plan/01-*.md`.

## Risks

- If `shek_brain` API shifts again, we'll need a `v0.3`. Mitigate by *not shipping v0.2* until `shek_brain` v0.1.0 has integration tests passing.
